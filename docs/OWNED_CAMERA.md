## Producer and consumers

### Current profile family and view

only the required owner branches: disabled owners use the default family; model-2
owners can select a control-flag variant; model-3 owners can substitute an actual
state-90 parent's class. Substitution does not recursively apply the model-2
variant test or another parent lookup. The variant flag's gameplay meaning is
unassigned. Unrecognized classes use the native default family.

Scaled input selects view one from the controlled actor's state kind, independently
of its model class and of the current camera owner. That override occurs before
the bounded Rust table-view check. Other out-of-range views refuse; the native
unchecked address calculation is not accepted as an additional profile.

`from_session` reads current owned headers, typed attachment parents and state
storage on every invocation, using checked `camera_owner::State` and shared
`camera_mode::State`. Foreign/retired actors, missing queried fields, unacquired
PC profiles and quarantined camera states refuse. An unqueried controlled actor
is not spuriously consumed. No family/view snapshot persists across commands.
The required `Catalog` supplies coefficients separately for each resolution;
there is no successful default, embedded original table or claimed binary identity
for a caller-provided catalog. Existing mode/lens validation remains responsible
for the values it consumes.

20,580 full original-PC/Rust contexts agree on 41,160 family/view words. They
execute the actual native profile getter and its predicates, varying controlled
model class and state independently, owner flags/variant, parent class/state,

These controls use synthetic valid actor identities; they do not compare profile
coefficients, current input devices, projection, live scheduling or GPU output.

### Session-bound owner-selection prefix

status, with explicit initial values. An eligible retained owner precedes an
override; otherwise an enabled nonnull override precedes the controlled actor.
A missing controlled actor leaves the existing words untouched. Negative indices
and disabled owners skip reference preparation without clearing its old status.
The new owner is published before the required reference service, while success
status follows its return. Errors retain callback effects and quarantine replay.

this checked owner; mode/force/profile producers and enclosing order stay explicit.

### Shared mode commands and Session pre-world composition

`camera_mode::State` now implements the acquired shared mode command and camera
eligibility policy. It requires explicit initial words. Raw command `-1` follows
the source's extended-mode policy and is not treated as a generic view toggle.
Mode stores precede any eligible owner-scale write. The current profile is queried
again before clearing the transition scalar and setting projection; its second
result cannot be replaced by the first. Invalid commands retain mode/view but
still execute that final profile/projection sequence. A provider failure retains
completed stores and quarantines further mode commands and admission queries.
Profile selection, actor-scale writes and actual projection remain required
services; there is no silent backend.

The activation-time `reset_projection` entry resolves the current profile,
clears the transition and publishes projection with the acquired flags. It does
not select a camera owner, change mode/view or write actor scale. A profile
failure leaves the transition intact; a later projection failure retains its
completed reset and quarantines shared commands/admission.
The native type-activation caller invokes this in its session-mode-zero branch,
before later actor initialization and initial animation selection. The separate
non-mode-four damage-authority rule does not establish activation eligibility.
The existing collapsed cold CPU constructor is
not an execution checkpoint for this earlier service. Preserve that order when
binding the application's still-pending projection reset.

## Validation and boundaries

### Ordered subjective camera production - 6 November 2026

`mecc_world_camera::State` binds the ordinary producer to one Session source and
separates world-frame numbering from camera invocation numbering. An active
subjective frame performs an inner call after virtual animation selection and
before placement, first ANM/reference publication and fire. Its outer call runs
after post completion. The following frame cannot replace either unfinished
obligation. Only the matching completed outer publication is eligible for rendering.
The mission inspection driver now uses that outer publication and reads camera
inputs directly from the completed Session source.
`Publication::frame()` identifies the world frame; its output's `number` identifies
the camera invocation. Future consumers must retain that distinction when a world
frame contains both calls.

`Session::advance_mecc_subjective_post_produced` accepts no numeric camera packet.
It supplies placement with the previous actual camera globals and the generated
inner result, and replaces fire's camera/origin/forward before executing the real
callback. Known startup globals are an explicit boundary; an unknown initial
camera cannot enter subjective placement. Missing/stale owners or phases refuse
before providers run. A failed camera pass retains its last completed diagnostic
publication and refuses replay; it cannot become a new rendered view.

Four continuous native/Rust controls now pass 320 frames, 144 inner calls and 320
outer calls, twelve shots and 404,560 normalized state/cache/view words. Numeric
camera inputs in the private runner are deliberately invalid; Rust produces both
the prior immediate-fire view and the current subjective view. The controls retain
their original source/held/virtual references, projectile, FX, RNG and epoch checks.
A further 64-frame control captures the native inner renderer upload and matches

Two synthetic sequence controls and a source-backed three-case lifecycle control
